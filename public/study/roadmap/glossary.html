원시타입 Primitive Type CH01

문자열·숫자·불리언·null·undefined·bigint·symbol처럼 값 자체가 그대로 저장되고 복사되는 타입이다. 변수에 담긴 원시값은 서로 독립적이라 하나를 바꿔도 다른 변수에 영향을 주지 않는다.

왜 중요한가 — 참조타입과 구분하지 못하면 "복사했는데 같이 바뀐다" 류의 버그를 이해할 수 없다.

한 줄 예 — let a = 1; let b = a; b = 2; // a는 그대로 1

참조타입 Reference Type CH01

객체, 배열, 함수처럼 변수에 값이 아니라 메모리 주소(참조)가 저장되는 타입이다. 같은 참조를 가진 두 변수는 한쪽을 수정하면 다른 쪽도 함께 바뀐다.

왜 중요한가 — React에서 "state가 안 바뀐다"는 버그 대부분이 참조타입을 직접 변형해서 생긴다.

한 줄 예 — const a = { n: 1 }; const b = a; b.n = 2; // a.n도 2

스코프 Scope CH01

왜 중요한가 — 스코프를 알아야 변수 충돌과 클로저 동작을 예측할 수 있다.

한 줄 예 — if (true) { let x = 1; } // x는 여기서 접근 불가

렉시컬 스코프 Lexical Scope CH01

함수가 호출된 위치가 아니라 코드가 작성된 위치를 기준으로 상위 스코프가 정해지는 규칙이다. JS는 실행 시점이 아니라 정의 시점의 스코프 체인을 따른다.

왜 중요한가 — 클로저가 왜 바깥 변수를 계속 기억하는지 설명하는 근거다.

한 줄 예 — function outer() { let x = 1; return function () { return x; }; }

호이스팅 Hoisting CH01

왜 중요한가 — "선언 전에 썼는데 에러가 안 나고 undefined가 나온다" 같은 동작을 이해하는 데 필요하다.

한 줄 예 — console.log(x); var x = 1; // undefined, 에러 아님

TDZ Temporal Dead Zone CH01

let/const로 선언된 변수가 스코프 시작부터 실제 선언문까지 접근이 금지되는 구간이다. 이 구간에서 변수를 참조하면 ReferenceError가 발생한다.

왜 중요한가 — var와 달리 let/const가 왜 더 안전한지 설명하는 핵심 개념이다.

한 줄 예 — console.log(y); let y = 1; // ReferenceError

클로저 Closure CH01

왜 중요한가 — 카운터, 캐시, 프라이빗 변수 흉내 등 상태를 함수 안에 안전하게 가두는 패턴의 기반이다.

한 줄 예 — const counter = (() => { let n = 0; return () => ++n; })();

this CH01

왜 중요한가 — 이벤트 핸들러나 콜백 안에서 this가 undefined가 되는 흔한 버그의 원인이다.

한 줄 예 — const obj = { n: 1, get() { return this.n; } };

왜 중요한가 — 콜백 안에서 this를 따로 bind하지 않아도 되게 해준다.

왜 중요한가 — class 문법도 결국 프로토타입 기반으로 동작하므로 원리를 알아야 상속 버그를 디버깅할 수 있다.

이벤트 루프 Event Loop CH01

왜 중요한가 — setTimeout과 Promise의 실행 순서를 예측하려면 반드시 알아야 한다.

콜스택 Call Stack CH01

왜 중요한가 — 스택이 너무 깊어지면 "Maximum call stack size exceeded" 에러가 발생한다(무한 재귀 등).

한 줄 예 — function f() { f(); } f(); // stack overflow

왜 중요한가 — 마이크로태스크보다 항상 나중에 실행된다는 순서 규칙을 알아야 한다.

왜 중요한가 — async/await 뒤의 코드가 setTimeout보다 먼저 실행되는 이유가 여기에 있다.

Promise CH01

왜 중요한가 — 콜백 지옥 없이 비동기 흐름을 체이닝(.then/.catch)하거나 async/await로 다룰 수 있게 해준다.
