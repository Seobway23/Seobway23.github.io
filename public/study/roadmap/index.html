§1프론트엔드란 무엇인가

웹 서비스는 크게 두 덩어리다. 프론트엔드는 사용자가 직접 보고 만지는 화면을 만들고, 백엔드는 데이터를 저장하고 계산해서 프론트엔드에 넘겨준다.

프론트엔드 개발자가 실제로 다루는 것은 결국 세 가지 언어와 그 위에 얹힌 도구들이다.

HTML — 구조

문서에 무엇이 있는지 정의한다. 제목, 문단, 버튼, 입력창. 뼈대에 해당한다. → CH09

CSS — 표현

그것들이 어떻게 보이는지 정의한다. 색, 크기, 배치, 반응형, 애니메이션. → CH06

JavaScript — 동작

사용자 행동에 어떻게 반응하는지 정의한다. 클릭 처리, 서버 통신, 화면 갱신. → CH01

아래 예제가 그 셋이 합쳐진 최소 단위다. 오른쪽 코드를 직접 고치고 ▶ 실행을 눌러보면 바로 아래 결과가 바뀐다. (단축키: 코드 영역에서 Ctrl + Enter)

세 줄로 읽는 코드

  • <button> — HTML. "여기 버튼이 하나 있다"는 구조 선언.
  • <style> 안의 규칙 — CSS. 그 버튼을 어떻게 보이게 할지.
  • addEventListener — JavaScript. 눌렀을 때 무슨 일이 일어날지.

고쳐볼 것 — background 색을 바꿔보고, count + 1을 count + 10으로 바꿔서 실행해봐라. 코드를 바꾸면 결과가 바뀐다는 이 감각이 전부의 시작이다.

지금 이해 안 돼도 정상이다 위 코드의 addEventListener가 뭔지 몰라도 된다. CH01에서 처음부터 다룬다. 지금은 "HTML은 구조, CSS는 모양, JS는 동작"만 남기면 충분하다.

§2브라우저는 어떻게 화면을 그리는가

주소창에 URL을 치고 화면이 보이기까지, 브라우저는 정해진 순서를 밟는다. 이 순서를 알면 "왜 CSS는 <head>에 넣고 스크립트는 defer를 붙이나", "왜 이미지 크기를 미리 지정해야 하나" 같은 실무 규칙이 전부 설명된다[2].

§3왜 React·TypeScript·빌드 도구가 필요한가

§1의 예제처럼 document.getElementById로 직접 DOM을 만지는 방식은 화면이 10개 요소를 넘어가는 순간 무너진다. "지금 화면 상태가 뭐지?"를 사람이 머릿속으로 추적해야 하기 때문이다.

React — 화면을 함수로

화면을 컴포넌트라는 작은 함수로 쪼개고, 상태가 바뀌면 React가 바뀐 부분만 다시 그린다. → CH03, CH04

TypeScript — 실수를 미리

"이 값은 문자열", "이 함수는 숫자를 받는다"를 코드에 적어두면, 실행 전에 편집기가 틀린 곳을 빨간 줄로 알려준다. → CH02

Vite — 코드를 브라우저용으로

브라우저는 TypeScript도, React 문법(JSX)도 모른다. 빌드 도구가 이를 번역하고 하나로 묶는다. → CH07

Yarn Berry — 남의 코드 관리

React 같은 외부 패키지를 설치·버전 고정·공유하는 도구. Berry는 node_modules 없이 동작하는 PnP 방식을 쓴다. → CH07

같은 화면을 두 방식으로 만들면 차이가 바로 보인다.

React 버전이 하는 일

  • useState로 "지금 개수"라는 상태를 선언한다.
  • 화면(JSX)은 그 상태를 그대로 읽어 쓴다 — {items.length}.
  • setItems로 상태만 바꾸면, 화면 갱신은 React가 한다. DOM을 직접 만지는 코드가 한 줄도 없다.

여기서 React.useState처럼 React.를 붙인 이유는 이 플레이그라운드가 import 없이 동작하는 환경이기 때문이다. 실제 프로젝트에서는 import { useState } from 'react'로 쓴다.

§6이 학습서 사용법

① 상단 탭으로 챕터 이동

화면 맨 위 탭바에서 챕터를 누르면 이동한다. 각 챕터 안에서는 왼쪽 목차로 대단원을 오간다. 맨 아래 이전/다음 버튼으로 순서대로 진행할 수도 있다.

② 점선 밑줄에 마우스 올리기

이런 단어에 커서를 올리면 뜻이 뜬다. 키보드만 쓴다면 Tab으로 이동해도 뜬다.

③ 오른쪽 코드는 직접 고친다

코드 영역은 편집 가능하다. 값을 바꾸고 ▶ 실행(또는 Ctrl+Enter)을 누르면 결과가 갱신된다. 망가뜨렸으면 되돌리기를 누른다.

④ 각주 [n]은 근거다

문장 끝 [1] 표시를 누르면 챕터 하단 참고 문헌으로 간다. 전부 공식 문서 링크이며, 의심되면 원문을 직접 확인하는 게 맞다.

⑤ 모르는 단어는 용어사전

용어사전에 180개 이상의 용어를 정의·예시·챕터 링크와 함께 정리해뒀다. 검색창에 한글/영문 아무거나 넣으면 필터링된다.

⑥ 체크리스트로 진도 관리

각 챕터 끝의 "이해도 점검" 체크박스는 브라우저에 저장된다. 체크가 안 되는 항목이 있으면 그 절로 돌아가라.

실행 환경에 대한 정직한 고지 오른쪽 코드 실행기는 React 18 UMD + Babel Standalone을 CDN에서 불러와 브라우저 안에서 직접 컴파일한다. 따라서 인터넷 연결이 필요하고, import 문과 외부 npm 패키지(예: @tanstack/react-query)는 쓸 수 없다. 그런 경우 본문에서는 동작 원리를 담은 40줄 내외의 미니 구현을 실행 가능한 형태로 보여주고, 실제 라이브러리 코드는 옆에 정적 코드 블록으로 병기한다. 또한 이 실행기는 TypeScript 타입을 지우고 실행하므로 타입 에러는 잡히지 않는다 — 타입 검사는 TS Playground에서 확인한다.

§7전체 챕터

시작 전 체크

  • 크롬(또는 엣지) 최신 버전을 쓰고 있다 — 예제가 최신 CSS/JS를 쓴다
  • 개발자 도구를 여는 법을 안다 (F12 또는 Ctrl+Shift+I)
  • Node.js LTS가 설치돼 있다 — CH07부터 필요하다 (node -v로 확인)
  • VS Code 같은 편집기가 준비돼 있다
