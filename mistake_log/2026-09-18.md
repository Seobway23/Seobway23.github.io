# 2026-09-18 오답로그

## PR #32 생성 (feature/concept-graph-roadmap → main)

### 1) 환경변수 이름을 확인 없이 `GITHUB_TOKEN` 이라고 안내했다

**증상** — 사용자에게 `setx GITHUB_TOKEN <토큰>` 을 시켰는데, 실제로 MCP GitHub 서버가 읽는 변수는
`GITHUB_PERSONAL_ACCESS_TOKEN` 이었다. 토큰을 제대로 넣었는데도 인증이 계속 실패했고,
나중에 값을 다른 이름으로 복사하는 불필요한 단계를 한 번 더 거쳤다.

**원인** — "GitHub 토큰 환경변수 = `GITHUB_TOKEN`" 이라는 일반 통념(gh CLI 관례)을 그대로 적용했다.
**설정 파일을 먼저 읽고 변수명을 확인한 뒤 안내했어야 하는데, 안내를 먼저 하고 확인을 나중에 했다.**

**수정** — `~/.claude/` 를 grep 해서 `GITHUB_PERSONAL_ACCESS_TOKEN` 을 쓰는 걸 확인하고,
기존 값을 그 이름으로 복사했다.

**재발 방지** — 사용자에게 환경변수·설정 키 이름을 **시키기 전에** 해당 설정 파일을
먼저 grep 해서 실제 키 이름을 확인한다. 통념으로 안내하지 않는다.

### 2) 안 쓰이는 템플릿 설정을 보고 원인으로 지목할 뻔했다

**증상** — `mcp-configs/mcp-servers.json` 에 `"GITHUB_PERSONAL_ACCESS_TOKEN": "YOUR_GITHUB_PAT_HERE"`
플레이스홀더가 박혀 있는 걸 보고 "이 리터럴이 환경변수를 덮어쓴다" 고 원인 진단을 냈다.
실제로 로드되는 건 `plugins/cache/ecc/ecc/1.10.0/.mcp.json` 이었고, 거기엔 env 블록이 아예 없어
부모 프로세스 환경을 상속하는 구조였다.

**원인** — grep 이 잡아준 **여러 후보 파일 중 어느 것이 실제로 로드되는지 확인하지 않고**,
내용이 그럴듯한 파일 하나를 골라 결론으로 삼았다. 파일이 3벌(사용자 설정 / 플러그인 캐시 /
마켓플레이스)로 중복 존재한다는 점을 무시했다.

**수정** — 플러그인 루트의 `.mcp.json` 을 직접 읽어 실제 로드되는 설정을 확인했다.

**재발 방지** — 설정 파일이 여러 벌 잡히면 **"어느 것이 실제 로드본인가"를 먼저 판정**한 뒤
원인을 말한다. 중복 설정 저장소(플러그인 캐시·마켓플레이스·사용자 설정)는 기본적으로
템플릿일 수 있다고 본다.

### 3) 403 원인을 권한 항목으로만 좁혀 안내해, 사용자가 UI 에서 헤맸다

**증상** — `pull_requests=write` 없다고만 알려주고 "Pull requests 를 Read and write 로 바꿔라" 고 했다.
사용자 화면에는 Repository permissions 섹션 자체가 없었다(Account permissions 만 보였다).
Repository access 가 `Public repositories`(read-only) 로 잡혀 있어 쓰기 권한 칸이 나타나지 않는
상태였고, 사용자가 "여기서 뭘 하라는거임" 으로 되물어서야 알았다.

**원인** — 응답 헤더(`x-accepted-github-permissions`)가 가리키는 **최종 권한만 보고**,
그 권한을 켤 수 있으려면 먼저 Repository access 를 `Only select repositories` 로 바꿔야 한다는
**UI 의 선행 조건을 생략**했다. 내 머릿속 최종 상태를 사용자 현재 화면과 맞춰보지 않았다.

**수정** — Repository access → 레포 선택 → 그때 나타나는 Repository permissions 순으로
단계를 다시 풀어서 안내했다.

**재발 방지** — 외부 웹 UI 설정을 시킬 때는 **최종 설정값이 아니라 도달 경로(클릭 순서)** 로 적는다.
선행 선택이 바뀌어야 나타나는 항목이면 그 선행 단계부터 쓴다.
