# 2026-10-16 오답로그

### 1) 머지 보고 때 「배포는 안 돈다」를 먼저 말하지 않았다

**증상** — PR #39 머지를 끝냈다고 보고했고, 사용자가 「푸쉬 ㄱㄱ」 다음에야 Actions 가 안 돈 것을 알았다. 「머지는 했는데 actions 이 안돌았다는건가?」 라고 되물었다.

**원인** — push 트리거를 끈 것이 같은 날 내가 한 작업인데, 머지 결과를 git 상태(main = origin/main)로만 판단하고 「머지 = 사이트 반영」 이라는 사용자의 기대를 확인하지 않았다.

**수정** — Actions 실행 기록을 조회해 9/30 이후 실행이 없음을 보여 주고, push 트리거를 다시 켰다.

**재발 방지** — 머지를 보고할 때 build.yml 트리거를 확인하고 「배포가 도는지」를 한 줄로 같이 적는다. 실행 기록 API(`/actions/runs`)로 머지 sha 의 실행이 생겼는지 본다.

### 2) 워크플로 이름을 틀리게 안내했다

**증상** — 수동 실행 방법을 「build 워크플로」 라고 안내했다. Actions 탭에 보이는 이름은 「Build and Deploy」 다.

**원인** — 파일 이름(build.yml)을 화면 표시 이름으로 썼다. `name:` 줄을 보지 않았다.

**수정** — 다음 답에서 「Build and Deploy」 로 바로잡음.

**재발 방지** — 사용자에게 UI 경로를 안내할 때는 파일의 `name:` 값을 읽고 쓴다.

### 3) 배포 확인을 HTTP 200 과 제목으로만 했다

**증상** — 배포 후 microtask, emotion, css-cascade 가 200 이고 제목이 맞는 것만 보고 「사이트에 올라간 것 확인」 이라고 보고했다. 사용자는 바로 그 글들에서 seq 가 원문으로 보인다고 알려 왔다.

**원인** — 정적 HTML 이 응답하는 것과 화면 코드(hydrate)가 정상 동작하는 것을 같은 것으로 봤다. 배포가 두 번 연달아 돌아 해시 chunk 가 교체되는 상황을 고려하지 않았다.

**수정** — chunk 교체로 동적 import 가 실패하는 경로를 재현하고, `vite:preloadError` 새로고침과 블록별 try/catch 를 넣음.

**재발 방지** — 배포 확인은 브라우저로 글 하나를 열어 seq·playground 가 렌더됐는지(`.post-seq` 존재, 원문 `<pre>` 숨김)까지 본다.

### 4) 첫 가설로 「정적 HTML 에 원문이 박혀 있다」고 짚었다

**증상** — prerender 결과에 `language-seq` 원문이 있을 것이라 보고 정적 HTML 을 먼저 조회했으나 본문이 없었다.

**원인** — prerender 가 본문을 어떤 형태로 넣는지 확인하지 않고 일반적인 SSR 구조를 가정했다.

**수정** — gh-pages 커밋별 assets 목록을 비교해 chunk 삭제를 확인하고 원인을 바꿈.

**재발 방지** — 「브라우저에서만 보이는」 문제는 먼저 배포 산출물(gh-pages 트리) 차이와 콘솔 오류를 본다.

### 5) React 문서 예제를 기억으로 옮겨 적었다

**증상** — pure-function 글에 Strict Mode 예제를 `guests.push(1)` 배열 버전으로 썼다. React 문서 원문은 `let guest = 0; guest = guest + 1` 카운터다.

**원인** — 출력값(#2, #4, #6)만 확인할 생각이었고 코드 모양은 기억이 맞다고 가정했다.

**수정** — `lv45/react.mjs` 로 원문을 추출해 코드와 seq 를 문서와 같게 고침.

**재발 방지** — 「문서의 예」라고 쓰는 코드는 원문 텍스트를 추출한 뒤에 옮긴다.

### 6) 그림을 넣으면서 읽는 방식(확대)을 확인하지 않았다

**증상** — LV3·LV4·LV5 글에 960px 폭 SVG 를 7장 넣었지만 본문 폭에서 글자가 작고 클릭해도 커지지 않았다. 사용자가 「svg 클릭하면 확대되어 보일 수 있게 해야지」라고 지적했다.

**원인** — 그림이 렌더되는지(naturalWidth)만 확인했고, 본문 폭에서 12.5px 글자가 읽히는지는 보지 않았다. mermaid 에만 확대 모달이 있다는 것을 알면서 img 에는 적용하지 않았다.

**수정** — 본문 img 에 기존 확대 모달을 연결.

**재발 방지** — 그림을 넣으면 실제 본문 폭(모바일 포함)에서 캡처해 글자가 읽히는지 본다.

### 7) 훅이 막는 `| head`·`| tail`·`grep` 를 세 번 연달아 썼다

**증상** — TS 실습 키트 작업 중 Bash 호출 3번이 `ban-raw-tools.ps1` 훅에 차단됐다(`BLOCKED pipe '| head'`, `'| tail'`, `raw 'grep'`). 매번 다시 보냈다.

**원인** — 첫 차단 메시지를 "그 명령 하나"의 문제로 읽고, 훅 규칙이 "Bash 에서 출력 거르기 전부 금지"라는 걸 일반화하지 않았다. 그래서 다음 호출에서 다른 필터 명령으로 같은 일을 반복했다.

**수정** — 출력은 파일로 리다이렉트한 뒤 Grep 도구로 필요한 줄만 읽었다.

**재발 방지** — 이 환경 Bash 에서는 `|` 필터·`grep`·`head`·`tail` 를 쓰지 않는다. 긴 출력은 `> 파일` 로 받고 Grep/Read(offset) 로 본다.

### 8) README 에 검증 안 한 타입 동작을 먼저 적었다

**증상** — `const b = echo(42)` 가 `42` 로 추론된다는 설명을 README 에 쓴 뒤에야 tsc 로 확인했다(결과는 맞았음).

**원인** — 리터럴 넓히기 규칙을 기억으로 확신하고, "아티팩트와 다르다"는 반박성 주장을 확인 순서보다 먼저 적었다.

**수정** — 프로브 파일로 `Expect<Equal<typeof b, 42>>`·`let` → `number` 를 tsc 로 확인 후 삭제.

**재발 방지** — 원문을 반박하는 문장은 프로브로 확인한 다음에 쓴다.
