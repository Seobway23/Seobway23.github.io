# 2026-09-22 오답로그

## 글 표지 SVG 생성기 + 콜아웃 재디자인

### 1) SVG 안 `<style>` 에 꺾쇠를 그대로 써서 파일 전체가 깨졌다

**증상** — 첫 생성물을 크롬으로 열자 그림 대신 빨간 상자가 떴다.
`error on line 124 at column 10: Unexpected closing tag: {…/svg}style != {…/svg}object`.
CSS 주석에 적은 `인라인(<object>·inline SVG)으로` 의 `<object>` 를 파서가 여는 태그로 먹었다.

**원인** — HTML 감각으로 썼다. HTML의 `<style>` 은 raw text 라 안쪽 꺾쇠가 무해하지만,
**SVG는 XML이라 `<style>` 안도 마크업으로 파싱된다.** "스타일 블록 안은 안전하다" 는
전제를 형식(XML/HTML)에 따라 갈라 두지 않고 하나로 기억하고 있었다.

**수정** — `<style><![CDATA[ … ]]></style>` 로 감싸고, 주석에서 꺾쇠를 뺐다.

**재발 방지** — XML 계열(SVG·XHTML)에 `<style>`/`<script>` 를 넣을 때는 **먼저 CDATA로 감싸고**
시작한다. 그리고 생성 직후 헤드리스 크롬으로 한 번 렌더해서 눈으로 본다 —
이번에도 그 렌더가 아니었으면 깨진 파일을 그대로 넘길 뻔했다.

---

### 2) 읽히게 만들겠다고 표지의 내용을 덮었다

**증상** — 1차 레이아웃은 가운데에 불투명 패널(1048×570)을 깔았다. 렌더해 보니
배경에 깔아 둔 그 글의 코드가 왼쪽 귀퉁이 한 줄만 남기고 전부 가려졌다.
"글마다 다른 표지" 라는 목적 자체가 사라진 그림이었다.

**원인** — "제목이 배경 위에서 안 읽힌다" 는 문제를 **가장 센 수단(불투명 면)** 으로 먼저 풀었다.
그 배경이 장식인지 내용인지를 따지지 않았다. 코드는 장식이 아니라 이 표지의 콘텐츠였다.

**수정** — 패널을 지우고 가운데만 어두워지는 타원 비네트 + 제목 그림자로 바꿨다.
코드는 가장자리에서 살아 있고 가운데에서만 눌린다.

**재발 방지** — 무언가를 가리는 요소를 넣기 전에 "가려지는 쪽이 내용인가 장식인가" 를 먼저 적는다.
내용이면 가림 대신 **대비**(그림자·비네트·굵기)로 푼다.

---

### 3) 한 문서에 여러 장 인라인될 가능성을 설계에 안 넣었다

**증상** — 호버를 살리려면 카드가 SVG를 DOM에 인라인해야 한다는 결론이 난 **뒤에야**,
`id="ga"` · `.title` · `@keyframes spin` 이 전부 문서 전역이라는 게 보였다.
목록에 카드가 열 장이면 열 번째가 첫 번째의 그라데이션을 쓰고 강조색이 옆 글 것으로 바뀐다.

**원인** — 출력 형식만 보고 **소비되는 맥락**을 안 봤다. "SVG 파일 하나" 로만 생각했고,
그 파일이 어디에 어떻게 놓이는지(한 문서에 여러 장)는 나중 문제로 미뤘다.

**수정** — 생성 마지막 단계에 `namespaceSvg()` 를 두고 id·클래스·keyframes·`svg:hover` 전부에
슬러그 접두어를 붙였다. 두 장을 한 문서에 넣고 렌더해 서로 안 섞이는 걸 확인했다.

**재발 방지** — 자산을 만들 때 "이게 몇 개가 한 화면에 올라가는가" 를 먼저 묻는다.
1개 초과면 전역 이름(id·class·animation·CSS 변수)은 처음부터 네임스페이싱한다.

---

### 4) 그리디 줄바꿈으로 마지막 줄에 두 글자만 남겼다

**증상** — "원시 타입 — 값 자체가 복사되는 것들" 이 `… 복사되는` / `것들` 로 끊겼다.
표지 한가운데에 두 글자짜리 고아 줄이 남았다.

**원인** — 줄바꿈을 폭 초과 시점에서 끊는 그리디로만 짰다. 줄바꿈의 목표를
"넘치지 않기" 로만 두고 "고르게 나누기" 를 조건에 안 넣었다.

**수정** — 줄 수는 고정한 채 폭을 12px씩 좁혀 가며 줄 간 폭 차가 가장 작은 배치를 고르는
`balancedWrap()` 을 넣었다.

**재발 방지** — 제목·헤드라인처럼 **크게 보이는 텍스트**의 줄바꿈은 그리디로 끝내지 않는다.

### 5) 공유 카드가 SVG 를 못 그린다는 걸 사용자가 먼저 지적했다

**증상** — 표지를 SVG 로만 만들고 `coverImage` 에 그대로 꽂았다. 사용자가
"메타데이터 폼으로 svg가 안 나오지 않냐, 안 나오면 캡처본 사진이 필요하다" 고 짚어 줬다.
맞는 지적이다 — 카카오톡·트위터·페이스북·슬랙 어디도 `og:image` 의 SVG 를 그리지 않는다.
그대로 뒀으면 **링크를 붙일 때마다 표지 없는 카드**가 나갔을 것이다.

**원인** — SVG 의 제약을 `<img>` 안에서 `:hover` 가 안 온다는 **한 가지만** 확인하고 멈췄다.
"이 파일이 어디에서 소비되는가" 를 사이트 안(카드·히어로)까지만 세고,
**사이트 밖(공유 카드·크롤러)** 은 목록에서 빠뜨렸다. 3번 오답과 같은 뿌리다 —
소비 맥락을 끝까지 세지 않았다.

**수정** — `scripts/rasterize-thumbnails.mjs` 로 크롬이 같은 SVG 를 1200×630 으로 굽고
sharp 가 JPEG(q86)로 줄인다(470KB → 71KB). `prerender.mjs` 의 `ogImageFor()` 가
`.jpg` → `.png` → `.svg` 순으로 찾아 `og:image`·`twitter:image` 에 넣는다.
빌드해서 `dist/post/scope.html` 이 `.jpg` 를 가리키는 것까지 확인했다.

**재발 방지** — 자산을 만들면 **소비처를 끝까지 적고 시작한다**: 화면 안 / 공유 카드 /
검색 크롤러 / 인쇄 / 메일. 형식 하나로 전부 못 덮으면 그 자리에서 두 벌을 만든다.

### 6) BOM 이 있는 글의 제목을 통째로 날렸다

**증상** — 11개 중 2개(`settimeout-vs-promise`, `js-event-loop-and-async`)의 표지에
제목 대신 **슬러그**가 찍혔다. "settimeout-vs-promise" 가 그대로 표지 한가운데 박혔다.

**원인** — frontmatter 를 `/^---\r?\n/` 로 잡았는데 그 두 파일은 `﻿`(BOM)로 시작한다.
정규식이 안 맞아 frontmatter 전체가 빈 객체가 됐고, 제목은 파일명으로 떨어졌다.
**같은 폴더의 파일이라도 인코딩이 같다고 가정**한 것이 틀렸다.

**수정** — `stripBom()` 을 `readFrontmatter`·`firstCodeBlock` 입구에 뒀다.

**재발 방지** — 파일을 읽어 앞에서부터 패턴을 맞추는 코드는 **BOM 제거를 첫 줄에 둔다.**
그리고 일괄 생성은 결과를 한 줄씩 훑어본다 — 이번에도 출력 로그에 제목이 찍혀 있어서 잡혔다.

### 7) 헤드리스 가상시간에서 나온 결과를 코드 버그로 읽었다

**증상** — 플레이그라운드 렌더 칸 접기/펴기를 검증하면서 `chrome --headless --virtual-time-budget`
으로 세 가지 케이스를 돌렸다. "300ms 뒤에 그리는 예제" 가 `paint:false` 로 남아
**내 판정 로직이 비동기 렌더를 못 잡는다**고 결론 냈다. 실제로는 로직이 멀쩡했고,
가상시간 아래에서 **iframe 안 타이머가 진행되지 않은 것**이었다(진단용 600ms 메시지조차 안 왔다).

**원인** — 계측 도구의 한계를 피검체의 결함으로 읽었다. 실패를 봤을 때
"코드가 틀렸나" 만 세우고 "측정이 틀렸나" 를 가설에 안 넣었다.

**수정** — 타이머를 안 쓰는 동기 케이스로 좁혀 로직이 도는 걸 먼저 확인하고,
CDP(`--remote-debugging-port` + Node 22 내장 WebSocket)로 **실제 시간이 흐르는** 크롬에 붙어
`false → true` 전이를 확인했다.

**재발 방지** — 헤드리스 가상시간은 **정적 렌더 확인용**으로만 쓴다.
타이머·네트워크·지연 마운트가 얽힌 검증은 처음부터 CDP 로 실제 시간에서 본다.

### 8) "React 칸이 안 펴진다" 고 단정했는데 실행 전이었다

**증상** — CDP 로 `/post/closure` 를 열어 보니 `console-only` 에 `height=0px` 이라
**react 예제가 잘못 접힌다**고 판단했다. 실제로는 플레이그라운드가 화면 밖이어서
IntersectionObserver 가 아직 `run()` 을 안 부른 상태였다 — iframe 이 비어 있으니 접힌 게 맞다.
스크롤해서 넣으니 `height=260px` 로 정상 확장됐다.

**원인** — 지연 실행(lazy) 설계를 내가 그 파일에서 방금 읽고도 검증 시나리오에 반영하지 않았다.
"보이지 않는 요소는 아직 실행되지 않았을 수 있다" 를 확인 목록에 안 넣었다.

**수정** — 검증 스크립트에 `scrollIntoView` + 대기를 넣었다.

**재발 방지** — 지연 실행·지연 로딩이 있는 UI 를 자동 검증할 때는
**대상 요소를 뷰포트로 끌어온 뒤** 상태를 읽는다.

### 9) 푸시 직후 바로 머지해서 커밋 하나를 흘렸다

**증상** — 용어 치환 수정(`7b3d3ff`)을 푸시하고 곧바로 PR #33 을 머지했다.
머지 커밋 `e4ce707` 의 부모는 `9932936` 이었다 — **방금 올린 커밋이 빠진 채 합쳐졌다.**
main 에 `splitOutCode` 가 없었고, 그대로 뒀으면 사용자가 지적한 버그가 라이브에 남는다.
PR #34 를 따로 열어 같은 커밋을 다시 올려 해결했다.

**원인** — "푸시 성공 = PR head 갱신 완료" 라고 가정했다. 둘은 다른 시스템이고
GitHub 쪽 반영에 시간차가 있다. 게다가 푸시 출력이 `* [new branch]` 로 나온 것을
이상하게 보고도(같은 브랜치에 두 번 연속 그렇게 나왔다) 넘어갔다 — 신호가 있었는데 읽지 않았다.

**수정** — 머지 뒤 `git log -1 --format="%P"` 로 부모를 확인해 누락을 발견하고 PR 하나 더.

**재발 방지** — 머지 전에 **PR 의 head SHA 와 로컬 HEAD 가 같은지 본다.**
머지 직후에는 `main` 을 당겨 **기대한 파일이 실제로 들어갔는지 한 줄로 확인**한다
(이번 경우 `splitOutCode` 문자열 검색). 푸시하고 바로 머지하지 않는다.
