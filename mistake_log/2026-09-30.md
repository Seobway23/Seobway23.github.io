### 1) 이틀 전 새 글 4개를 AI 문체 그대로 썼다 (사용자 지적)

**증상** — 사용자가 "AI 티 난다. 제목·설명에 — 붙이는 것, 추상적인 말" 을 지적했다.

**원인** — "기존에 만들던 거 그대로 적용" 을 문체까지 복제하라는 뜻으로 읽었다.
기존 글의 대시 제목, 비유, 굵게 남용을 따라야 할 형식으로 보고 품질을 판단하지 않았다.
여기에 "이해 쉽게" 를 비유를 늘리는 쪽으로 해석해 문제를 더 키웠다.

**수정** — 문체 기준(제목표 · 대시 제거 · 비유→용어 대응 · 금지 문구)을 만들어 15개 전부를 고쳤다.

글을 다 쓰면 `—` 개수와 굵게 개수를 세고, 비유 단어(상자 · 줄 · 맡긴다)를 grep 한다.
→ 이 블로그 문체는 메모리 `feedback` 에 올린다.

### 2) 선행 글의 기술 오류를 보고도 지나쳤다 — Array.prototype.toString

**증상** — prototype 글의 seq 가 "toString 은 Array.prototype 에 없어 Object.prototype 으로 올라간다" 고 설명했다.

**원인** — 기존 글을 형식 참고용으로만 읽고, 내용이 사실인지 검증하지 않았다.

**수정** — 예시를 `hasOwnProperty`(Object.prototype 에만 존재)로 바꿨다.

**재발 방지** — 체인·순서를 설명하는 예시는 콘솔에서 `Object.hasOwn(Array.prototype, "x")` 처럼 한 줄로 확인한 뒤 쓴다.

### 5) Bash 에서 cat · head · grep · find 를 써서 훅에 네 번 막혔다

**증상** — `ban-raw-tools` 훅이 raw `cat`/`head`/`grep`/`find` 를 차단. 같은 세션에서 네 번.

**원인** — 한 번 막힌 뒤에도 파이프 조합 명령에 습관적으로 같은 도구를 끼웠다.

**수정** — Read · Grep · Glob 과 node 스크립트로 바꿨다.

**재발 방지** — 이 환경의 Bash 명령에는 cat/head/tail/grep/find 를 넣지 않는다. 파일 확인은 Read(limit), 검색은 Grep, 목록은 ls/Glob.

### 9) 차트 원시 데이터 JSON 이 .gitignore 의 `*.json` 에 걸려 저장소에서 빠질 뻔했다 (커밋 전 점검으로 발견)

**증상** — 로컬에서는 차트가 그려지지만 `git check-ignore` 로 보니 `public/post-assets/**/*.json` 이 전부 무시 대상. 그대로 PR 을 올리면 CI 빌드가 「chart source 없음」 으로 멈춘다.

**원인** — 차트 기능이 `public/` 의 JSON 을 읽게 만들면서, 저장소가 JSON 을 통째로 무시한다는 걸 확인하지 않았다. 로컬 렌더 성공을 「배포 가능」 으로 여겼다.

**수정** — `.gitignore` 에 `!public/post-assets/**/*.json` 예외. 서비스 계정 키 · `posts.json` 은 여전히 무시되는 것을 확인.

**재발 방지** — 빌드가 읽는 새 파일 종류를 만들면 커밋 전에 `git check-ignore -v` 로 그 파일이 추적되는지 본다.
