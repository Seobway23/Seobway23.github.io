### 1) sticky 가 깨진 원인을 코드만 보고 한 곳으로 단정할 뻔했다

**증상** — 첫 답변에서 원인을 `layout.tsx:32` 의 `overflow-x-hidden` 하나로 지목했다.
실제로 브라우저에서 재보니 `html`(index.css:71) · `body`(index.css:83) · `div.min-h-screen`
**세 곳 모두** 스크롤 컨테이너가 되어 있었다. 한 곳만 고쳤으면 여전히 안 붙었다.

**원인** — `overflow-x: hidden` → `overflow-y: auto` 승격이라는 **규칙은 알았지만**,
그 규칙이 몇 군데에 걸렸는지는 확인하지 않고 "가장 그럴듯한 한 곳"을 답으로 냈다.
원인 규칙을 아는 것과 적용 지점을 다 찾는 것은 별개다.

**수정** — 브라우저에서 sticky 요소의 조상 체인을 훑어 `overflowY`/`scrollHeight`/`clientHeight`
를 전부 찍었다. 세 곳을 `overflow-x: clip` 으로 바꾸고, 고친 뒤 `scrollY 2500` 에서
`top === 96px` 인지 다시 측정해 확인했다.

**재발 방지** — CSS 원인을 지목하기 전에 **문제 요소의 조상 체인을 실제로 덤프한다.**
"이 속성이 원인" 까지만 말하지 말고 "이 속성이 여기 여기 여기에 있다" 까지 확인하고 말한다.

### 2) 정보 구조를 안 보고 CSS로 때웠다 — 스크롤바 2개

**증상** — 사이드바가 뷰포트보다 길어지는 문제를 `max-h + overflow-y-auto` 로 막았다.
사용자가 "스크롤바가 2개 나와서 안 좋다"고 지적했다.

**원인** — "사이드바가 길다"를 **레이아웃 문제로만** 봤다. 실제로는 사이드바 4개 카드 중
3개(글 정보·태그·작성자)가 본문 헤더·본문 하단과 **완전히 중복**이라 애초에 있으면 안 되는
것이었다. 왜 긴지를 묻지 않고 길다는 사실만 처리했다.

**수정** — 중복 카드 3개 삭제, 목차만 남김. 작성자 소개는 글 하단으로 이동.
결과적으로 사이드바 높이 1000px → 357px, 스크롤바 0개.

**재발 방지** — "넘친다/길다" 류의 문제는 **자르기 전에 내용물이 다 필요한지 먼저 센다.**
같은 정보가 화면 안에 두 번 나오는지 확인하는 것을 첫 단계로 둔다.

### 3) `<script type="text/plain">` 안에 HTML 이스케이프를 했다

**증상** — 플레이그라운드 실행 시 `Uncaught SyntaxError: Unexpected token ')'`.
iframe 문서를 덤프해 보니 코드가 `setTimeout(() =&gt; ...)` 로 들어가 있었다.

**원인** — `<script>` 는 **raw text element** 라 HTML 파서가 엔티티를 디코딩하지 않는다.
`textContent` 로 읽으면 `&gt;` 가 그대로 나온다. "HTML 안에 텍스트를 넣을 땐 이스케이프"
라는 일반 규칙을 요소 종류를 따지지 않고 적용했다.

**수정** — 코드를 DOM 에 넣지 않고 `window.__PG_SRC = ${JSON.stringify(code)}` 로 넘기고,
문자열 안의 `<` 만 `<` 로 바꿔 `</script>` 로 블록이 끊기는 것을 막았다.

**재발 방지** — `<script>`·`<style>`·`<textarea>` 안에 값을 넣을 때는
**HTML 이스케이프가 아니라 그 언어의 리터럴 인코딩**(JS면 `JSON.stringify`)을 쓴다.

### 4) 공유되어야 할 사양을 한쪽에만 두고, 임시방편으로 중복을 남겼다

**증상** — ` ```seq ` 의 preset 사양을 `src/lib/post-sequence.ts` 안에만 뒀더니
프리렌더(`scripts/prerender.mjs`)가 `preset: event-loop` 만 적힌 글에서 아무 텍스트도
못 뽑았다. 고치는 과정에서 `_UNUSED_PRESETS_REFERENCE` 라는 죽은 중복 리터럴을 남겼다.

**원인** — 기능을 "브라우저에서 그리는 것"으로만 설계했다. 같은 사양을 빌드 타임에도
읽어야 한다는 걸 SEO 검증 단계에 가서야 알았다. 게다가 급히 고치면서 지워야 할 옛 코드를
지우지 않고 이름만 바꿔 남겼다 — 그건 수정이 아니라 부채다.

**수정** — `shared/seq-presets.mjs` 로 빼서 브라우저·빌드 스크립트가 같은 파일을 읽게 했다.
중복 리터럴 61줄은 삭제했다.

**재발 방지** — 새 문법을 만들 때 **"빌드 타임에도 이 내용을 읽어야 하나"** 를 먼저 묻는다.
읽어야 하면 `shared/` 에 둔다. 그리고 리팩터 중 만든 `_UNUSED_*` 는 그 커밋 안에서 지운다.

### 6) 다크 테마에서만 확인하고 "된다"고 보고했다

**증상** — 플레이그라운드 iframe 안의 색을 `color:#e5e7eb` 로 하드코딩했다.
라이트 테마로 바꾸니 밝은 배경에 밝은 회색 글자 → **버튼이 아예 안 보였다.**
사용자에게 이미 "react 마운트 확인" 이라고 보고한 뒤였다.

**원인** — iframe 은 별도 문서라 부모의 CSS 변수(`hsl(var(--foreground))`)가 안 먹는다는 건
알고 색을 직접 넣었는데, **"직접 넣는다 = 한 벌만 있으면 된다"** 로 넘어갔다.
그리고 검증을 다크 테마 한 벌로만 했다.

**수정** — `frameCss(dark)` 로 두 벌을 만들고 실행 시점 테마를 넣는다.
테마 토글을 실제로 눌러 srcdoc 색이 `#1f2937` ↔ `#e5e7eb` 로 바뀌는 것까지 확인.

**재발 방지** — **화면에 뭘 그렸으면 라이트/다크 둘 다 찍어 본다.** 이 저장소는 다크가
기본이라 라이트를 빼먹기 쉽다. 특히 **부모 CSS가 안 닿는 영역(iframe·canvas·SVG 인라인 스타일)**
은 테마 값을 손으로 넘겨야 하므로 항상 두 벌인지 확인한다.

### 7) 데스크톱 배치만 상정하고 좌표를 잡았다

**증상** — `seq` 화살표 시작·끝점을 레인 **상단(y+18)** 으로 고정했다.
모바일(390px)에서 레인이 2열로 접히자 화살표가 아래 줄 레인의 **라벨을 관통**했다.

**원인** — 레인이 항상 한 줄로 나란히 있다고 가정했다. CSS 로는 이미 2열로 접히게
만들어 놓고, 좌표 계산은 1열 가정으로 짰다. **같은 기능의 두 부분이 서로 다른 가정 위에 있었다.**

**수정** — 앵커를 레인 세로 중심으로 바꾸고, 같은 줄이면 위로 넘기고 다른 줄이면
옆으로 휘게 분기(`sameRow`). 모바일에서 다시 찍어 확인.

**재발 방지** — `getBoundingClientRect()` 로 좌표를 잡는 코드를 쓰면 **반응형 분기점마다
한 번씩 찍어 본다.** CSS 에 `@media` 를 넣은 순간 JS 좌표 가정도 같이 검토한다.

### 8) 기존 코드를 확인하지 않고 감시자를 새로 달았다

**증상** — 테마 전환 시 iframe 색을 갱신하려고 `MutationObserver` 를 붙였다.
그런 다음 `post.tsx` 를 보니 하이드레이션 `useEffect` 의 deps 가 이미 `[post, theme]` 라
테마가 바뀌면 **어차피 통째로 다시 만들어지고 있었다.** 내가 넣은 감시자는 중복이었고,
재하이드레이션마다 하나씩 쌓여 `disconnect()` 도 없는 누수였다.

**원인** — "테마 변화를 어떻게 감지하지?" 를 **새로 만들 문제**로 놓고 바로 코드를 썼다.
이 저장소가 이미 그 문제를 어떻게 풀고 있는지 먼저 안 봤다.

**수정** — 감시자를 지우고, 실행 시점에 `isDarkTheme()` 을 읽는 것만 남겼다.
기존 재하이드레이션에 얹는 쪽이 코드도 적고 누수도 없다.

**재발 방지** — 전역 상태(테마·라우팅·스크롤)에 반응하는 코드를 새로 붙이기 전에
**기존 컴포넌트가 그 상태를 이미 구독하는지 먼저 grep 한다.** 대개 이미 하고 있다.

### 9) `.prose` 안에 넣는 요소인데 선택자 격을 안 맞췄다

**증상** — 플레이그라운드 편집기의 하이라이팅 `<pre>` 와 `<textarea>` 를 포갰는데
글자가 어긋났다. 재보니 `<pre>` 는 `font-size 16px / padding 16px`, `<textarea>` 는
`12.48px / 13.6px` 였다. 내가 쓴 `.post-pg__hl` (0,1,0) 을 기존 `.prose pre` (0,1,1) 이
이기고 있었다.

**원인** — 같은 파일 안에서 다른 블록들은 전부 `.prose .post-tabs` 처럼 `.prose` 를
붙여 놨는데, 편집기 규칙만 클래스 하나로 썼다. **바로 위에 있는 선례를 안 봤다.**

**수정** — 편집기 관련 7개 선택자에 `.prose` 를 붙였다. 붙인 뒤 브라우저에서
`getComputedStyle` 로 두 요소의 글꼴·줄높이·padding 이 같은지, 좌상단이 1px 안에
겹치는지 재서 `aligned: true` 를 확인했다.

**재발 방지** — 본문(`.prose`) 안에 들어가는 요소의 CSS 는 **무조건 `.prose` 를 붙여
쓴다.** 그리고 겹쳐 놓는 UI 는 눈으로 보지 말고 `getComputedStyle` 비교로 검증한다.

### 10) 툴팁을 "닫는 조건"만 보고 "머무는 조건"을 안 만들었다

**증상** — 용어 툴팁 안의 "관련 글" 링크를 누를 수 없다는 지적을 받았다.
`mouseout` 에서 곧바로 `close()` 를 부르고 있었고, 툴팁은 `createPortal` 로
`document.body` 에 붙어 있어 **용어의 자식이 아니다.** 그래서 툴팁 쪽으로
마우스를 옮기는 8px 사이에서 무조건 닫혔다.

**원인** — 원래 코드가 "설명을 잠깐 보여주는 것"까지만 상정했다. 그 안에 **누를 수 있는
링크가 생긴 뒤에도** 닫기 로직을 그대로 뒀다. 내용이 상호작용 가능해지면
수명 규칙도 같이 바뀌어야 하는데 놓쳤다.

**수정** — (1) 닫기를 220ms 유예로 바꾸고 (2) 패널의 `onMouseEnter` 가 그 예약을
취소하게 하고 (3) 클릭하면 고정되는 상태를 추가했다.
브라우저에서 9단계 시나리오(호버→이탈→패널 진입→링크 확인→이탈 닫힘→클릭 고정→
고정 중 이탈→토글 닫기)를 전부 통과시켰다.

**재발 방지** — 마우스를 떼면 사라지는 UI 안에 **누를 수 있는 것을 넣는 순간**,
"떠나는 경로"가 존재하는지 먼저 확인한다. 포털로 옮긴 요소는 DOM 부모가 아니므로
`contains()` 기반 판정이 통하지 않는다는 것도 같이 기억한다.

### 11) 글자를 그리는 요소가 아니라 그 부모만 맞췄다 → 사용자가 커서 어긋남을 발견

**증상** — 사용자가 스크린샷으로 지적: 플레이그라운드에서 **커서가 글자보다 한 줄 아래**에
찍힌다. 재보니 `<textarea>` 는 12.48px/20.59px, `<code>` 는 **11.09px/18.30px** 였다.
줄마다 2.29px 씩 밀려 7줄이면 16px ≈ 한 줄.

**원인** — 9번을 고칠 때 `.prose` 를 붙이면서 **`<pre>` 만** 맞췄다. 하지만 글자를 실제로
그리는 건 그 안의 `<code>` 이고, `.prose code` 가 `font-size: 0.875em` 을 따로 걸고 있었다.
"부모를 맞췄으니 됐다"고 보고 자식을 확인하지 않았다. 게다가 그때 내가 짠 검증 스크립트가
**`code.parentElement`(=pre) 와 textarea 를 비교**하고 있어서 `styleMatch: true` 라는
잘못된 초록불을 냈다.

**수정** — `.prose .post-pg__hl code` 에 `font: inherit` 등을 걸어 물려받게 했다.
검증도 고쳤다: 20줄을 넣고 `Range` 로 각 줄 첫 글자의 실제 y 를 재서 textarea 가 그릴
위치와 비교 → 누적 오차 **2.29px/줄 → 0.03px/20줄**.
이어서 가로 스크롤도 어긋나 있던 것(`.prose pre code` 의 `overflow:auto` 때문에 code 가
자체 스크롤 컨테이너가 되어 `pre.scrollLeft` 가 먹지 않음)을 `overflow: visible` +
`width: max-content` 로 고쳤다.

**재발 방지** — 두 요소를 픽셀 단위로 포갤 때는 **글자를 실제로 그리는 말단 요소**끼리
비교한다. 그리고 **검증 스크립트가 무엇과 무엇을 비교하는지** 먼저 확인한다 —
엉뚱한 쌍을 비교하면 통과 신호가 오히려 문제를 덮는다.

### 13) 같은 정보를 두 곳에 적는 설계를 문서에 먼저 써 버렸다

**증상** — 개념 그래프 설계안 초안에 글 frontmatter 로 `prereq: [scope, hoisting]` 을
적게 해 놓았다. 그런데 `concepts.yml` 에도 개념 정의가 있어야 한다. 구현에 들어가서야
**같은 선행 관계를 두 곳에 적게 되는 구조**임을 알아채고 설계를 바꿨다.

**원인** — "글을 쓰는 사람이 한 파일만 열게 하자"는 편의를 먼저 생각했다.
그런데 `prereq` 는 **개념의 성질이지 글의 성질이 아니다.** 소유자가 누구인지를
먼저 정하지 않고 편의부터 정했다.

**수정** — `prereq`·`track`·`level` 전부 `concepts.yml` 로 몰고, 글은 `concept:` 한 줄만
적게 했다. 설계 문서 §2-1 도 고치고 "왜 양쪽에 적으면 안 되는지"를 명시했다.
`build-concept-graph.mjs` 에 **한 개념을 두 글이 주장하면 빌드 실패**를 넣었다.

**재발 방지** — 필드를 어디에 둘지 정할 때 **"이 값은 무엇의 성질인가"** 를 먼저 묻는다.
편의는 그 다음이다. 두 곳에 적히는 구조가 보이면 그건 설계 오류지 취향이 아니다.

### 14) 셀렉터 하나로 확인하고 "TOC 가 안 뜬다"고 오해할 뻔했다

**증상** — 샘플 글 검증에서 `document.querySelectorAll('aside nav a').length` 가 0 이라
목차가 깨진 줄 알았다. 실제로는 멀쩡했다. 콜아웃(`<aside class="post-callout">`)이
사이드바보다 DOM 앞에 있어서 `querySelector('aside')` 가 콜아웃을 집었고,
목차 항목은 `<a>` 가 아니라 `<button>` 이었다.

**원인** — 이전 글에는 콜아웃이 없어서 `aside` = 사이드바가 성립했다.
**그때 통하던 셀렉터를 새 글에서도 그대로 썼다.** 게다가 목차가 버튼인지 링크인지
컴포넌트를 안 보고 `a` 로 단정했다.

**수정** — `[...document.querySelectorAll('aside')].find(a => a.querySelector('.toss-card'))`
로 특정하고, 버튼 개수와 텍스트로 확인했다(8개 섹션 정상).

**재발 방지** — 검증 셀렉터는 **그 페이지에서 유일함을 먼저 확인**하고 쓴다.
0 이 나오면 "기능이 깨졌다"가 아니라 **"셀렉터가 틀렸다"를 먼저 의심**한다.
→ 11번(검증 스크립트가 엉뚱한 쌍을 비교)과 같은 뿌리다. **2회 반복.**
→ 승격: 아래 규칙으로 올린다.
