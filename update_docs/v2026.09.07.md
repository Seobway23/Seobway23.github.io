# 2026.09.07-01 — 글에서 개념을 "돌려 보는" 블록 4종 + 검색 노출

## 기능 확장

**단계 재생 다이어그램 (` ```seq `)** — 이벤트 루프처럼 "무엇이 어디로 가는가"를
설명할 때, 그림 대신 재생되는 다이어그램을 넣을 수 있다. 코드를 짜지 않고
`lane`(상자)과 `step`(장면)만 줄로 적으면 된다. 독자는 `▶` 재생, `‹` `›` 한 단계씩,
또는 `←` `→` 키로 직접 따라간다. 화살표가 움직이는 경로를 그린다.
내장 예제 `event-loop`·`http-request` 는 한 줄(`preset: event-loop`)로 불러온다.

**라이브 플레이그라운드 (` ```playground `)** — 독자가 본문 안에서 코드를 고쳐
바로 실행한다(`Ctrl+Enter`). `import` 문이 실제로 동작해서 React 훅이든 npm 패키지든
그대로 쓸 수 있고, `console.log` 결과는 아래 콘솔 패널에 찍힌다.

**본문 탭 (`::: tabs`)** — 같은 층위의 개념 A·B·C 를 세로로 늘어놓는 대신
탭으로 묶는다. 탭 안에 표·수식·코드·콜아웃을 모두 넣을 수 있고, 키보드로도 넘긴다.

**좌우 2단(`::: split`)·카드 격자(`::: grid`)·체크리스트(`- [ ]`)** 추가.

## 개선

**목차가 스크롤을 따라온다.** 기존에도 고정하도록 되어 있었지만 CSS 설정이 서로
충돌해 실제로는 붙지 않았다. 이제 글을 아무리 내려도 목차가 화면에 남는다.

**오른쪽 사이드바를 목차만 남기도록 정리.** 글 정보·태그·작성자는 본문에 이미
있던 내용이라 같은 것을 두 번 보여주고 있었고, 그 때문에 사이드바가 화면보다
길어져 스크롤바가 두 개 생겼다. 중복을 걷어내니 스크롤바가 사라졌다.
작성자 소개는 글 맨 아래로 옮겼다.

**검색·AI 답변에 글이 잡히도록 정적 페이지를 생성한다.** 지금까지 이 블로그는
브라우저에서 자바스크립트를 실행해야 본문이 보이는 구조였다. 자바스크립트를
실행하지 않는 AI 크롤러에게는 빈 페이지였다. 이제 빌드 때 글마다 본문이 들어간
HTML 을 만들고, 글별 제목·요약·대표 이미지·구조화 데이터와 `sitemap.xml`·
`robots.txt` 까지 생성한다.

## 수정

- 플레이그라운드 코드에 `=>` 가 들어가면 실행되지 않던 문제 수정.
- 라이트 테마에서 플레이그라운드 실행 결과가 배경에 묻혀 보이지 않던 문제 수정.
  테마를 바꾸면 실행 화면 색도 따라간다.
- 휴대폰에서 시퀀스 다이어그램의 화살표가 아래 칸 제목을 가로지르던 문제 수정.

# 2026.09.07-02 — 용어 툴팁을 붙잡을 수 있고, 코드 색을 고를 수 있다

## 수정

**용어 툴팁 안의 "관련 글" 을 이제 누를 수 있다.** 지금까지는 용어에서 마우스를
떼는 순간 툴팁이 사라져서, 그 안의 링크로 가는 것이 불가능했다. 두 가지를 고쳤다.

- 용어에서 마우스가 벗어나도 잠깐 기다린다. 그 사이 툴팁 위로 마우스를 옮기면 유지된다.
- **용어를 클릭하면 툴팁이 고정된다.** 고정 중에는 마우스가 어디로 가든 닫히지 않고,
  같은 용어를 다시 누르거나 `닫기`·`Esc`·바깥 클릭으로 닫는다.

## 기능 확장

**코드 색상 테마를 고를 수 있다.** 헤더의 팔레트 아이콘 → **화면 설정** 맨 위에
`코드 색상 테마` 가 생겼다. GitHub · Atom One · Stack Overflow · Tokyo Night ·
고대비 · JetBrains/VS 여섯 가지. 고르면 본문 코드 블록과 플레이그라운드 편집기에
동시에 적용되고, 다음 방문에도 유지된다. 라이트/다크 짝이 있어 화면 테마를 바꿔도
느낌이 이어진다. 고르는 자리에 실제 색이 적용된 미리보기가 함께 나온다.

## 개선

**플레이그라운드 편집기에 문법 강조가 들어갔다.** 지금까지 편집 영역은 전부
같은 색이라 읽기 어려웠다. 이제 키워드·문자열·주석·함수명이 구분되고,
위에서 고른 코드 테마를 그대로 따른다.

# 2026.09.07-03 — 글이 서로 이어지는 학습 지도의 토대

## 기능 확장

**개념 그래프가 생겼다.** 이제 글을 "개념" 단위로 등록하면 학습 순서가 자동으로
계산된다. 어떤 글을 읽기 전에 무엇을 알아야 하는지, 읽고 나면 어디로 가야 하는지가
사람 손이 아니라 그래프에서 나온다.

- 글쓴이는 선행 관계 한 줄만 적는다 (`prereq: [스코프, 호이스팅]`)
- 난이도 레벨 · 학습 순서 · "다음 읽을 글" · 트랙 진도는 전부 자동
- 순서가 꼬이면(예: 선행보다 먼저 나오는 글) 배포 전에 걸린다

첫 트랙 **JavaScript 코어** 를 열었다. 스코프 → 호이스팅 → 클로저 세 글이 올라갔고,
기존 이벤트 루프 글이 비동기 트랙에 연결됐다.

**모든 개념 글의 출처를 기계가 검사한다.** MDN · ECMAScript 사양 · WHATWG ·
W3C 같은 1차 공식 문서만 인용할 수 있고, 개인 블로그를 출처로 달면 배포가 막힌다.
확인한 날짜도 함께 적어, 6개월이 지나면 다시 확인하라고 알려 준다.

## 개선

**새 글 3개** — 스코프 · 호이스팅 · 클로저. 각각 5~8분 분량이고,
움직이는 다이어그램과 직접 고쳐 돌리는 코드가 들어 있다.

# 2026.09.07-04 — 학습 지도가 화면에 나왔다

## 기능 확장

**로드맵 페이지가 생겼다.** 상단 메뉴 `로드맵` 에서 볼 수 있다.
위쪽이 기초, 아래로 갈수록 그 위에 쌓이는 개념이고, 선은 "이걸 알아야 저게 보인다"는
뜻이다. 카드를 누르면 글로 가고, 동그라미를 누르면 읽음으로 표시된다.
진도는 이 브라우저에 남는다.

- 노드에 마우스를 올리면 그 개념의 선행·후행만 남아 길이 뚜렷해진다
- 아직 글이 없는 개념은 점선으로 표시된다 — 앞으로 채울 자리가 보인다
- 선행을 아직 안 읽은 개념에는 자물쇠가 붙는다

**카테고리마다 `리스트 | 로드맵` 을 고를 수 있다.** 예를 들어 `frontend` 를 열면
글 목록으로 볼지, 개념 지도로 볼지 오른쪽 위에서 전환할 수 있다.
지도가 있는 카테고리에서만 이 전환이 나타난다.

**AI 검색에 잡히도록 `llms.txt` 를 만든다.** ChatGPT·Claude·Perplexity 같은
AI 검색이 사이트를 한 번에 파악할 수 있게, 글 목록과 한 줄 요약, 그리고
**무엇을 먼저 읽어야 하는지(선행 관계)** 까지 담은 파일을 배포마다 생성한다.

## 글 쓰는 사람에게

`posts/README.md` 에 위 기능 전부의 문법·예시·주의사항을 정리했다.
글을 고친 뒤에는 여전히 `npm run generate:posts` 를 실행해야 반영된다.
