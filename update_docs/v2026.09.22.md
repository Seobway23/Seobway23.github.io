# 2026.09.22-01 — 글마다 다른 표지, 그리고 조용해진 콜아웃

## 기능 확장

**글 표지를 그 글의 코드로 만든다.** 지금까지 표지는 카테고리마다 정해진 로드맵
이미지 하나를 돌려 썼다. 목록을 훑으면 같은 그림이 네다섯 번씩 반복됐다.

이제 표지는 글에서 직접 뽑아 그린다.

| 표지에 들어가는 것 | 어디서 오는가 |
|---|---|
| 가운데 제목 | frontmatter `title` (한글 폭까지 재서 줄을 고르게 나눈다) |
| 그 아래 한 줄 | `excerpt` |
| 배경에 깔린 코드 | **본문 첫 코드 블록** — 문법 색까지 입혀서 |
| 강조색·칩 | `category` (사이드바·카드와 같은 색 규칙) |
| 글로우·별 배치 | slug — 같은 글은 늘 같은 자리, 다른 글은 다른 자리 |

그래서 같은 템플릿인데도 글마다 다른 그림이 나온다. 파일은 SVG라 20KB 안팎이고,
어떤 화면 배율에서도 글자가 뭉개지지 않는다.

```
npm run thumb -- posts/frontend/javascript/primitive-type.md
npm run thumb -- posts/frontend/javascript --write-frontmatter
```

**표지가 움직인다.** 글로우가 천천히 흐르고, 별이 깜빡이고, 빛줄기가 한 번씩
지나가고, 코드 끝의 커서가 점멸한다. 목록 카드와 글 상단 표지 모두에서 돈다.
마우스를 올리면 배경 코드가 또렷해지고 반짝임이 빨라진다.

움직임을 원하지 않는 사용자(OS의 "동작 줄이기" 설정)에게는 전부 정지된 상태로 보인다.

---

## 개선

**콜아웃(TIP·WARNING 박스)이 조용해졌다.** 파스텔 색면으로 문단 전체를 칠하고
굵은 색 막대와 대문자 라벨을 세우던 방식은, 읽는 흐름을 한 번 끊고 어느 문서에서나
본 듯한 얼굴을 만들었다.

바꾼 뒤에는

- 배경은 본문과 같은 색. 강조색은 위쪽에 7%만 스며든다
- 왼쪽 4px 막대 → 아래로 사라지는 3px 실선
- 라벨은 상자 **테두리 위에 걸터앉아** 본문 첫 줄을 밀어내지 않는다
- 색은 라벨 앞 점 하나로만 쓴다

종류(주의·팁·위험)는 여전히 한눈에 구분되지만, 본문을 가리지 않는다.
기존에 쓴 모든 글에 자동으로 적용된다 — 글을 고칠 필요는 없다.

# 2026.09.22-02 — JavaScript 글 11개에 새 표지, 공유 카드용 이미지 분리

## 기능 확장

**JavaScript 글 11개가 새 표지를 달았다.** 콜 스택 · 클로저 · 이벤트 루프 ·
실행 컨텍스트 · 호이스팅 · 원시 타입 · 참조 타입 · 프로토타입 · 스코프 ·
setTimeout vs Promise · 이벤트 루프 인터랙티브.

목록에서 훑어보면 이제 표지만으로 어느 글인지 갈린다 — 배경에 깔린 코드가 글마다 다르다.

**링크를 붙였을 때도 표지가 뜬다.** 카카오톡·트위터·페이스북·슬랙은 SVG 를 그리지 않는다.
사이트 안에서는 SVG(가볍고 선명하고 움직인다), 공유 카드에는 같은 그림을 구운
JPEG 을 쓰도록 나눴다. 장당 71KB — 원본 캡처(470KB)의 1/6이라 모바일에서도 금방 뜬다.

```
npm run thumb:png      # 표지 SVG 를 공유용 이미지로 굽는다
```

## 수정

**제목이 슬러그로 찍히던 두 글을 고쳤다.** `setTimeout vs Promise` 와
`JS 이벤트 루프와 비동기` 는 파일이 BOM 으로 시작해 제목을 못 읽고 있었다.
표지 한가운데에 `settimeout-vs-promise` 같은 파일명이 박히던 문제다.

# 2026.09.22-03 — 실행 예제의 빈 검은 칸이 사라졌다

## 수정

**콘솔만 쓰는 예제에서 빈 상자가 사라졌다.** 실행 예제는 오른쪽이 두 칸이다 —
위는 화면이 그려지는 칸, 아래는 콘솔. 그런데 `console.log` 로 결과를 보는 예제는
위 칸에 그릴 것이 없어서 **빈 검은 상자가 300px 그대로 남아 있었다.**

이제 예제가 실제로 화면에 무언가를 그렸을 때만 그 칸이 열린다. 안 그리면
콘솔이 그 자리를 전부 받아 로그가 훨씬 넓게 보인다.

판단은 예제 종류(`js`·`react`)로 하지 않는다 — `js` 예제도 화면을 그릴 수 있고
`react` 예제도 콘솔만 쓸 수 있기 때문이다. 실행된 코드가 실제로 그렸는지를 보고 정한다.
글을 쓸 때 따로 표시할 것은 없다.

# 2026.09.22-04 — 코드 안 `[[Prototype]]` 이 태그로 새어 나오던 것 수정

## 수정

**프로토타입 글에서 HTML 태그가 글자 그대로 보이던 문제를 고쳤다.**

`[[Prototype]]` 은 자바스크립트가 객체 안에 숨겨 둔 내부 슬롯의 표기법인데,
이 블로그의 용어 사전 문법(`[[termId]]`)과 생김새가 똑같다. 용어 치환이
**인라인 코드 안까지** 들어가는 바람에 `` `[[Prototype]]` `` 이 용어 링크로 바뀌었고,
그 태그가 코드 블록 안에 갇혀 독자에게 이렇게 보였다.

```
모든 객체는 내부에 <span class="glossary-term" data-term="Prototype" …>Prototype</span> 이라는
```

이제 용어 사전과 도메인 카드 치환은 **코드 안을 건드리지 않는다** — 수식(KaTeX)과 같은 규칙이다.
`` `[[Prototype]]` `` 은 코드로, 본문의 `[[termId]]` 는 용어 링크로 각각 제대로 나온다.
